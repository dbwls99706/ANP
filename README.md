# ANP — AI-Native Graph Runtime

> No source code. Just graphs and a runtime.

**ANP** is an AI-native runtime where software is defined as executable graphs instead of source code.

```
Prompt → LLM Planner → ANP Graph → ANP Runtime → Running Software
```

Other AI coding tools generate source code. ANP generates **executable graphs** — there is no source code, only graph definitions that the runtime executes directly.

## Demo

This REST API has **no source code** — just a graph:

```
┌──────────┐  GET /users   ┌──────────┐       ┌──────────┐
│  http    ├──────────────▶│ database ├──────▶│ console  │
│  server  │  POST /users  │  (KV)    │       │ (stdout) │
│  :3000   ├──────────────▶│          │       │          │
└──────────┘               └──────────┘       └──────────┘
   Service                   Processor             Sink
```

```bash
$ cargo run -p anp-cli -- run examples/simple_api.anp.json

 INFO HTTP server listening port=3000
 INFO all service nodes started, waiting for Ctrl+C...
```

Query the running API:

```bash
$ curl http://localhost:3000/users
{"count":2,"keys":["user:1","user:2"],"op":"list"}

$ curl -X POST http://localhost:3000/users \
  -H "Content-Type: application/json" \
  -d '{"op":"set","key":"user:3","value":{"name":"Charlie","age":35}}'
{"key":"user:3","op":"set","success":true}

$ curl http://localhost:3000/users
{"count":3,"keys":["user:1","user:2","user:3"],"op":"list"}
```

**There is no source code for this API** — only a [graph definition](examples/simple_api.anp.json).

## Why ANP?

```
Traditional:     Code → Compile → Run
AI coding tools: Prompt → Code → Compile → Run
ANP:             Prompt → Graph → Run
```

- **No source code** — software is defined as dataflow graphs
- **AI-native** — graphs are designed to be generated by LLMs
- **Runtime-first** — the runtime is stable; nodes are plugins
- **Node = Library** — the node ecosystem is the package manager

## Key Features

- **Graph-based software definition** — JSON spec, no compilation
- **Event-driven runtime** — Service nodes (HTTP, etc.) trigger downstream pipelines per-event
- **Parallel pipeline execution** — independent nodes in a stage run concurrently
- **Automatic mode detection** — batch or service mode based on graph content
- **Error port routing** — route errors to fallback pipelines
- **Built-in graph validation** — cycle detection, port existence, 6 rules total
- **CLI tools** — run, validate, info, explain, graph (DOT), init
- **LLM-ready architecture** — NodeSchema provides JSON Schema for AI planners

## Quick Start

### Prerequisites

- [Rust](https://rustup.rs/) (1.75+)

### Build

```bash
git clone https://github.com/dbwls99706/ANP_Tool.git
cd ANP_Tool
cargo build
```

### Run

```bash
# Hello world — read file and print
cargo run -p anp-cli -- run examples/hello.anp.json

# Data pipeline — file_read → transform → filter → console
cargo run -p anp-cli -- run examples/pipeline.anp.json

# HTTP API server — http_server → database → console
cargo run -p anp-cli -- run examples/simple_api.anp.json
```

### CLI Commands

```bash
anp run <graph>        # Execute a graph
anp validate <graph>   # Validate without executing
anp info <graph>       # Display graph structure
anp explain <graph>    # Human-readable explanation
anp graph <graph>      # Output GraphViz DOT format
anp init <name>        # Scaffold a new project
```

### Create a New Project

```bash
cargo run -p anp-cli -- init my-app
cd my-app
cargo run -p anp-cli -- run main.anp.json
# → Hello from my-app!
```

## How It Works

### 1. Define software as a graph

```json
{
  "nodes": [
    { "id": "read",  "node_type": "file_read", "kind": "source",
      "config": { "path": "data.txt" } },
    { "id": "print", "node_type": "console",   "kind": "sink" }
  ],
  "edges": [
    { "id": "e1", "from_node": "read", "to_node": "print" }
  ]
}
```

### 2. The runtime executes it

```bash
cargo run -p anp-cli -- run graph.anp.json
```

No compilation. No source code. Just a graph and a runtime.

## Architecture

```
┌─────────────┐
│  ANP Graph   │  JSON specification
└──────┬──────┘
       ↓
┌──────┴──────┐
│  Validator   │  6 validation rules (cycles, ports, edges...)
└──────┬──────┘
       ↓
┌──────┴──────┐
│  Scheduler   │  Topological sort → ExecutionPlan
└──────┬──────┘
       ↓
┌──────┴──────┐
│  Executor    │  Stage-by-stage parallel execution
└──────┬──────┘
       ↓
┌──────┴──────┐
│    Nodes     │  Pluggable node ecosystem
└─────────────┘
```

### Execution Modes

| Mode | Trigger | Behavior |
|------|---------|----------|
| **Batch** | No Service nodes | Source → Processor → Sink, then exit |
| **Service** | Has Service nodes | Start services → wait for events → Ctrl+C to stop |

### Node Kinds

| Kind | Description | Examples |
|------|-------------|----------|
| **Source** | Produces data (runs once) | `file_read` |
| **Processor** | Transforms data | `transform`, `filter`, `database` |
| **Sink** | Consumes data | `console`, `file_write` |
| **Service** | Long-running event loop | `http_server` |

### Built-in Nodes (v0.1)

| Node | Kind | Description |
|------|------|-------------|
| `console` | Sink | Print to stdout |
| `file_read` | Source | Read file content |
| `file_write` | Sink | Write data to file |
| `transform` | Processor | Dot-path field mapping |
| `filter` | Processor | Condition-based filtering (eq, gt, lt, contains...) |
| `http_server` | Service | HTTP server with route-based output ports |
| `database` | Processor | In-memory key-value store (get/set/delete/list) |
